🧭 Day 1 — The Blueprint · Date TBD Identify and define a precise, achievable problem — then map the entire workflow to reach the solution and divide it across the team's skillset.

9:00 – 10:001.1From Vague Idea to Precise Problem Statement

Goals

  1. Tell a problem statement apart from a solution statement, and rewrite a vague ask as a precise one
  2. Apply a scoping test — measurable outcome, data actually available, achievable in three days — to kill or keep an idea
  3. Write a one-sentence problem statement naming the user, the input, and the success criterion

10:00 – 11:001.2Mapping the Workflow to the Solution

Goals

  1. Decompose the problem into a stepwise workflow, from raw input to delivered output
  2. Name what each step needs — data, a tool, or a human decision — and what it hands to the next step
  3. Mark the riskiest, least-understood step on the map and decide how to de-risk it first

11:00 – 12:001.3Dividing the Work Across the Team

Goals

  1. Inventory the team's actual skills and assign every workflow step a single owner
  2. Define the handoff between owners — the shape of the data crossing each boundary — so parallel work integrates
  3. Leave with a task board: owner, deadline, and a definition of done for every Day 2 task

🔨 Day 2 — The Build · Date TBD Construct a 'happy path' prototype using low-code tools.

9:00 – 10:002.1Choosing Your Low-Code Stack

Goals

  1. Match each step of yesterday's workflow map to a specific low-code tool
  2. Stand the toolchain up end to end and push a trivial payload all the way through it
  3. Decide deliberately what to stub and what to build — protecting the three hours you actually have

Slides: TBD Review: TBD Materials: TBD Homework: TBD

10:00 – 11:002.2Building the Happy Path

Goals

  1. Implement each step against one known-good input — no edge cases, no error handling, not yet
  2. Connect the steps so a single input reaches a finished output with no manual intervention
  3. Snapshot the working version the moment it works, before adding anything else to it

11:00 – 12:002.3Making It Demoable

Goals

  1. Wrap the prototype in something a stranger can drive without you narrating
  2. Write a three-minute demo script with a scripted input and a known-good outcome
  3. Document what is stubbed, faked, or known-broken — this is Day 3's attack surface

⚔️ Day 3 — The Battle Test · Date TBD Rigorously peer-test prototypes to identify and harden against edge cases.

9:00 – 10:003.1Designing the Attack

Goals

  1. Build an edge-case inventory across the standard axes: empty, malformed, adversarial, out-of-scope, and at scale
  2. Turn that inventory into a concrete test script another team can execute without asking you questions
  3. Draw the line between outright failure and acceptable degradation before testing starts

Slides: TBD Review: TBD Materials: TBD Homework: TBD

10:00 – 11:003.2Peer Red-Team Round

Goals

  1. Break another team's prototype — run their script, then improvise past it
  2. Log every failure with reproduction steps and a severity, so it can be fixed without you in the room
  3. Receive your own failure log without defending, explaining, or arguing with it

Slides: TBD Review: TBD Materials: TBD Homework: TBD

11:00 – 12:003.3Hardening & Handoff

Goals

  1. Triage the failure log by severity against cost to fix, and commit to a cut line
  2. Fix what's above the line and re-run the exact tests that caught each one
  3. Present the honest version: what broke, what you fixed, and what you would fix next
